# Request Tracking Ledger

Checked: 2026-06-02

Purpose: track what happens after the compiler sends archival, reference, or
MDR requests. The request packet supplies the wording; this ledger records
status, response evidence, and the source-note or selection action triggered
by each response.

Spreadsheet export: [request tracking ledger CSV](request-tracking-ledger.csv).

For the current project status, use the
[compiler dashboard](compiler-dashboard.html). For the recommended send order
and closeout pages for each request, use the [compiler action
board](compiler-action-board.html), then use the [request send
sheet](request-send-sheet.html) for compact subject lines, routes, and control
links. Before any response changes a candidate to selected or
source-note-ready, run the [promotion gate
checklist](promotion-gate-checklist.html). For response classification, use
the [response triage sheet](response-triage-sheet.html), then capture exact
reply and release fields in the [response intake sheet](response-intake-sheet.html).

## Status Key

| Status | Meaning | Next action |
| --- | --- | --- |
| Not recorded | No sent date or response is recorded in this project. | Send the request or enter the sent date and tracking number. |
| Sent | Request has been submitted. | Add acknowledgement date, office, and assigned tracking number. |
| Acknowledged | Repository or agency confirmed receipt. | Calendar follow-up and wait for reference/MDR action. |
| Referred | Repository referred the record to another agency. | Record agency, referral date, and any new tracking number. |
| Partially released | Some responsive material is available, with withholdings. | Update source-note fields, decide whether to appeal/re-request withheld tabs, and classify selection value. |
| Released | Responsive material is available without material gaps. | Draft final source note and update selection worksheet. |
| Not located | Repository or agency did not locate the target. | Record search scope; decide whether to try another office or cite public fallback. |
| Closed | No further action needed. | Record FRUS action: select, support, editorial note, fallback, drop. |

## Response Capture Template

Use one row per response or release.

| Field | Fill in |
| --- | --- |
| Request ID | A1, B1, D1, etc. |
| Date sent | YYYY-MM-DD. |
| Office / agency | Exact office that received or answered. |
| Tracking number | Agency/repository tracking number, if assigned. |
| Response date | YYYY-MM-DD. |
| Result | Released, partially released, referred, not located, denied, still pending. |
| Files received | Exact filenames, scans, file units, page counts, or folder titles. |
| Withholdings / referrals | Exemptions, referred agencies, appeal/re-review path, or release limitations. |
| Source-note facts captured | Repository, series, OA/ID, folder, classification, document type, attachments, routing, annotations. |
| Selection action | Select, support only, editorial note, public fallback, more review, or drop. |
| Next action | Appeal, follow-up, agency referral, new request, scan request, source-note draft, or none. |

## Follow-Up Rules

| Situation | Action |
| --- | --- |
| Response provides only catalog metadata | Keep status as support/locator; do not promote selected-document status. |
| Response releases minutes or a summary of conclusions | Compare against the selection worksheet immediately; update source-note audit. |
| Response releases only withdrawal sheets | Keep as MDR target; record exemptions and decide whether appeal/re-review is worth it. |
| Response identifies a better file unit | Add a new request row and link it back to the original request ID. |
| Response says not located | Record search scope before trying another office; a narrow search is not proof the record does not exist. |
| Response releases a public fallback copy only | Use in editorial notes unless no archival control copy can be located. |
