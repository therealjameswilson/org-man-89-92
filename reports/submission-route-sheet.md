# Submission Route Sheet

Checked: 2026-06-02

Purpose: choose the right official route and evidence packet before sending a
request. This page sits between the [compiler action
board](compiler-action-board.html), the [research request
packet](research-request-packet.html), and the [request send
sheet](request-send-sheet.html).

Spreadsheet export: [submission route sheet CSV](submission-route-sheet.csv).

Use the official route page before submitting; forms, addresses, emails, and
special instructions can change. After sending, record the request in the
[request tracking ledger](request-tracking-ledger.html). When a response
arrives, classify it in the [response triage sheet](response-triage-sheet.html)
and capture exact source-note facts in the [response intake
sheet](response-intake-sheet.html).

## Send Packet Checklist

Before sending, confirm the packet includes:

- Request ID and candidate slot.
- Exact target and date range.
- Repository, agency, office, series, lot, NAID, OA/ID, local ID, or file unit.
- Public/control links and any public PDF, catalog, finding-aid, or withdrawal-sheet evidence.
- Response sought: reference guidance, scan/folder pull, MDR or re-review, referral status, metadata clarification, or fallback confirmation.
- Source-note fields needed before the candidate can close.
- Why the record matters to *FRUS, 1989-1992, Volume II, Organization and Management of Foreign Policy*.
- Parent request or tracking number if the request is a follow-up.

## Same-Pass Updates

After sending, update the [request tracking ledger](request-tracking-ledger.html)
before moving to the next row. If a response changes the route, add the new
route in the ledger, classify it in the [response triage
sheet](response-triage-sheet.html), capture the facts in the [response intake
sheet](response-intake-sheet.html), and use the [follow-up request
sheet](follow-up-request-sheet.html) for the next request.
